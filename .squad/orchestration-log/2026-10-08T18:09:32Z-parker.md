## Turn 1: Fixed Init-Container Interpreter Mismatch

**Status:** Completed  
**Commit:** b3c60a3  

Identified and fixed critical defect: `infra/k8s/harness.tf` ran the deploy init container with
`["python", "-m", ...]` but the deploy stack (`azure-ai-projects`) is installed only into
`/opt/deploy-venv`, which is never activated and never on PATH. The bare `python` command
invokes the system interpreter, which lacks the required module.

**Fix implemented:**
- Added `var.agent_deploy_interpreter` with default `/opt/deploy-venv/bin/python`
- Validated to be an absolute path (prevents silent failure from future PATH reordering)
- Updated init container spec to use `[var.agent_deploy_interpreter, "-m", var.agent_deploy_module]`
- Absolute path is deliberate: PATH-based resolution would make the pod covertly sensitive to any
  later `ENV PATH` edit in the Dockerfile

**Team notification:** Drift between `decisions.md`, Dockerfile, and `variables.tf` (module path,
interpreter path, venv path) is only caught by reading or by apply. No mechanical validation
exists. This class of defect is now known risk and documented.

## Turn 2: Removed `DeployedOn` Timestamp Tag

**Status:** Completed  
**Commit:** 64371ae  

Removed `timestamp()` function from `DeployedOn` tag in both `infra/cloud/locals.tf` and
`infra/spike/locals.tf`. This plan-time-varying function was marking the entire tag map as
unknown on every plan cycle, causing all tagged resources to be marked for in-place update.
Live plan showed 24 changes, 22 of them tag-only churn.

**Rationale:**
- No consumer consumed the `DeployedOn` tag; verified across tasks, scripts, docs, and KQL
- `Application` and `AppName` tags remain unchanged; both are consumed
- **Critical for demo control:** A clean plan (`No changes. Your infrastructure matches configuration.`)
  between Audit and Enforced runs is the mechanical proof that the RAI policy is the **only**
  variable between the two deployments

**Team rule established:** No `timestamp()`, `uuid()`, or `bcrypt()` anywhere in a persistent
resource attribute. Plan cleanliness is the control variable. Non-empty plans on unchanged
configurations are defects to be fixed, not noise to be scrolled past.

**Recorded as:** `docs/compatibility.md` §C6
